# AWMS Mobile — Setup Guide

## Important: why `android/` and `ios/` folders aren't included

This app was built in a sandboxed environment with **no network access and no
Android SDK / Xcode**, so I could not run `npx react-native init` or
`react-native run-android`/`run-ios` to generate and verify the native
project scaffolding. Hand-writing a full Gradle + AndroidManifest.xml +
MainActivity.java + Xcode `.xcodeproj` project byte-for-byte, without any way
to build or test it, would very likely produce a broken native layer — that
would be worse than being upfront about it. Native scaffolding is meant to be
generated by the official tooling, not authored by hand.

Everything that actually **is** the app — every screen, every line of
business logic, navigation, state, i18n, theming, API calls — is complete in
`src/`, `App.js`, and `index.js`. What's missing is the thin native shell
that RN CLI normally generates for you in about 60 seconds.

## One-time setup (run this once, on your machine, with internet access)

```bash
cd AWMS

# 1. Generate a fresh RN CLI project scaffold (creates android/ + ios/)
npx react-native init AwmsMobileScaffold --version 0.73.6 --package-name com.awms.mobile

# 2. Copy the native folders it just generated into this mobile/ folder
cp -r AwmsMobileScaffold/android mobile/android
cp -r AwmsMobileScaffold/ios mobile/ios
rm -rf AwmsMobileScaffold

# 3. Install this app's actual dependencies (already listed in mobile/package.json)
cd mobile
npm install

# 4. Link vector icon fonts (Android autolinks; iOS needs one manual step)
#    Android: react-native.config.js already points at the icon fonts, and
#    RN 0.73's autolinking handles most of it. If icons still don't show up
#    after a rebuild, add this line to android/app/build.gradle (at the
#    bottom) as a fallback:
#      apply from: "../../node_modules/react-native-vector-icons/fonts.gradle"
#    iOS: open ios/AwmsMobile.xcodeproj in Xcode, drag
#    node_modules/react-native-vector-icons/Fonts into the project,
#    and add each font filename to Info.plist under "Fonts provided by application".
#    (Full instructions: https://github.com/oblador/react-native-vector-icons#ios)

# 5. Run it
npx react-native run-android
# or
npx react-native run-ios
```

## Pointing the app at your backend
Edit `src/api/config.js`:
- Android emulator reaches your host machine via `10.0.2.2` (already set as the default).
- iOS simulator can use `localhost` directly (already set as the default).
- A real physical device needs your computer's LAN IP (e.g. `http://192.168.1.42:3000`) — the phone and your dev machine must be on the same Wi-Fi network.
- Production build: change the `default:` branch to your real deployed API URL.

## Login credentials
Same as the web dashboard — log in with a user created in the AWMS backend
(e.g. the seeded `admin@awms.local` account, or any user you create via the
web dashboard's Settings → Users screen).

## Admin vs. Customer/Staff dashboard — how the split actually works
The backend's `Role` model is fully **dynamic** (organizations create
whatever role names they want — "Warehouse Manager", "Operator", etc.).
There's no fixed `CUSTOMER` role in the schema to match against. This app
routes to the Admin dashboard if the logged-in user's `roleName` contains
"admin" (case-insensitive) — see `selectIsAdmin` in
`src/store/slices/authSlice.js` — and to the Customer/Staff dashboard
otherwise. If your organization uses different role-naming conventions,
update that one selector.

## Adding your app icon / splash image
The current splash screen is a pure-JS animated view (logo circle + text) —
no native launch-screen image is required, and it works identically on
Android and iOS with zero extra native configuration. If you'd rather show
your actual logo image on the very first native-rendered frame (before JS
even loads), that requires the platform-specific native splash setup
(`android/app/src/main/res/drawable/` + a style, or `ios/.../LaunchScreen.storyboard`)
— a natural next step once you have real brand assets and native tooling
available to test with.

## Verifying this hand-written JS layer
I syntax-checked every `.js`/`.jsx` file with the TypeScript compiler's
parser (in JS/JSX mode) since `npm install` wasn't possible here — every
file parses cleanly. I could **not** verify:
- That every imported package version in `package.json` is mutually compatible
- That the app actually boots on a real Metro bundler + device/emulator
- Runtime behavior of navigation, i18n, or the PDF/report download flows

**Please run `npm install` then `npx react-native run-android` (or `-ios`)
as your first step**, and treat this as a solid, complete first draft that
needs one real run-through rather than a guaranteed-working build.
